TypeScript · ESM + CJS · zero transitive dependencies · v0.5.0

Read, write and edit Excel.
Without breaking your file.

Libraries that rebuild a workbook from their own model lose whatever that model doesn't cover — charts, pivot tables, images, comments, conditional formatting. sheet-lite patches only what changed and carries every other ZIP part over byte-for-byte.

Quickstart API reference
  • ~149 ms to read a 5000 × 8 sheet
  • ~33 kB gzip, including deps
  • 0 transitive dependencies
  • fflate is the only dependency
  • Read-only streaming reads via sheet-lite/stream
  • Incremental bounded-memory writes via sheet-lite/write
  • 10.2 MB live heap streaming a 100 000 × 8 sheet

The public promise is “opens without repair.” Untouched parts of the file are preserved; when nothing changes, the original bytes are returned verbatim. Verified on our side with a real-file corpus and a LibreOffice gate in CI — LibreOffice is not Excel.

Why sheet-lite

The two most-downloaded spreadsheet packages on npm rebuild a workbook from their own model, so whatever that model does not cover is gone; one of them is frozen, with high-severity advisories that have no fix available. sheet-lite is built around a single principle: patch-only + copy-verbatim.

The preservation promise

  • Only the cells that actually changed are rewritten.
  • Data validations, conditional formatting, merges and images stay intact.
  • Styles and number formats are carried over per cell.
  • A no-op edit returns the original bytes exactly.
  • Charts, pivot tables, images and comments are preserved, not created.
  • Security by design: path-traversal, entry-count, size and compression-ratio limits.

Lightweight by construction

  • Only fflate — the ZIP + DEFLATE layer, 11.8 kB gzip, 0 transitive deps.
  • Runs on raw bytes: Node, browsers and edge runtimes.
  • TypeScript-first, shipped as both ESM and CJS.
  • Streaming lives behind its own entry point, so you only pay for it if you import it.
  • Filesystem access is lazy (node:fs/promises), so the core stays runtime-agnostic.

The preservation guarantee is verified on our side: 136 tests across 17 files, a corpus of 11 real .xlsx/.xlsm files (read, no-op byte-identity and a single-cell edit that leaves every other part identical), and a LibreOffice gate in CI that requires every edited corpus file to re-open without repair. LibreOffice is not Excel.

Benchmark

A 5000 × 8 workbook was generated with ExcelJS and read back with each library. Median read time and published package size (gzip, including dependencies):

Library Read (median) Size (gzip, incl. deps) Transitive deps
sheet-lite 149 ms ~33 kB 0
ExcelJS 192 ms 249.9 kB 9
SheetJS (xlsx) 218 ms 136.4 kB 7
sheet-lite ~33 kB
ExcelJS 249.9 kB
SheetJS 136.4 kB

sheet-lite's ~33 kB is 21 kB of library code (the main entry, gzip) plus 11.8 kB for fflate. Importing sheet-lite/stream adds a lazy chunk of ~3 kB gzip and sheet-lite/write a lazy chunk of ~7 kB gzip, both loaded on demand and only then. Reproduce the read numbers with pnpm bench.

Memory: streaming vs eager

A 100 000 × 8 worksheet read with StreamingWorkbook versus Workbook.read (pnpm bench:stream, 800 000 cells, fresh process per phase):

Metric Eager (Workbook.read) Streaming (sheet-lite/stream)
Live heap after GC 673 MB 10.2 MB
Read / walk time 2.87 s 3.21 s

Streaming reads a bounded set of small package parts plus one row at a time — ~66× less live heap here. It is read-only: editing needs the eager Workbook. Published sizes come from bundlephobia; read times from scripts/bench.mjs. All figures are medians on one machine (Node 24, Windows), ±10–15% cross-run variance.

What 0.5.0 actually ships

Everything below is in the published 0.5.0 package. Anything that is not there is listed under Limitations.

Read & edit

  • Workbook.read() / readFile() / toBuffer() / writeFile(), plus readBlob(), toBlob() and download().
  • Values: numbers, strings, booleans, dates (1900 & 1904), errors, formulas with their cached result, inline and shared strings.
  • Patch-only writes — only changed cells are re-serialized; a no-op edit returns the original bytes verbatim.
  • Merges: mergeCells() / unmergeCells().

Sheet structure

  • wb.addWorksheet(name, { views? }) and wb.removeWorksheet(nameOrId), with full OPC registration.
  • Works on files that have no styles.xml or no sharedStrings.xml.
  • Columns: ws.getColumn(n | 'A').width / .hidden — existing <cols> ranges are split, never destroyed.
  • Rows: row.height, written as a surgical <row ht="…"> patch.
  • Frozen panes: ExcelJS-style ws.views = [{ state: 'frozen', xSplit, ySplit }], read back on re-open.

Styles

  • cell.numFmt, cell.font (bold, italic, underline, size, name, ARGB color) and cell.fill.
  • cell.border with all 13 OOXML line styles, deduped in styles.xml and merged side-by-side over a cell's existing border.
  • cell.alignment: horizontal, vertical, wrapText, shrinkToFit, indent, textRotation, readingOrder.
  • Rich text read and write: { richText: [{ text, font? }, …] } from inline and shared strings, written as inline <r> runs.

Streaming & runtimes

  • Read-only streaming reads from sheet-lite/stream, or lazily via Workbook.openStream().
  • Incremental, bounded-memory writes from sheet-lite/write, or lazily via Workbook.create() (on main).
  • Bounded memory: a 100 000 × 8 sheet in 10.2 MB of live heap instead of 673 MB.
  • Identical values and types to the eager reader — same hardened ZIP layer, same rejection rules.
  • Browser and edge adapters: readBlob(), toBlob(), download().

Not created, only preserved: charts, pivot tables, images, comments, macros and conditional formatting. New worksheets are plain — values and optional frozen panes only. See Limitations for the full honest list.

Install

One package. One dependency. Nothing else is pulled in transitively.

bash 
npm install sheet-lite@0.5.0

Or with your package manager of choice:

bash 
pnpm add sheet-lite
yarn add sheet-lite

Requires Node ≥ 18. In browsers and edge runtimes, import the ESM build and work with raw bytes — no filesystem access needed. Streaming reads (sheet-lite/stream) and the incremental writer (sheet-lite/write) ship as subpath entry points, so the main bundle stays small; both are bundled with the package, so there is nothing extra to install.

Quickstart

Read a file, patch a cell and add a row — everything else stays byte-identical.

ts 
import { Workbook } from 'sheet-lite';

const wb = await Workbook.readFile('./report.xlsx');
const ws = wb.getWorksheet('Sheet1')!;

// Read a value and its type
console.log(ws.getCell('A1').value, ws.getCell('A1').type);

// Edit — only the changed cells are rewritten
ws.getCell('B2').value = 1234.56;
ws.getCell('B3').value = new Date();
ws.getCell('B4').value = { formula: 'SUM(B2:B3)', result: 1234.56 };
ws.getCell('B2').numFmt = '#,##0.00';
ws.getCell('A1').font = { bold: true };
ws.addRow(['North', 128]);

// Structure: columns, row heights, frozen panes
ws.getColumn('A').width = 24;
ws.getRow(1).height = 22;
ws.views = [{ state: 'frozen', xSplit: 0, ySplit: 1 }];

await wb.writeFile('./report-edited.xlsx');
// data validations, conditional formatting, images and other parts stay intact

Workbook.read() is synchronous and works on raw bytes: Workbook.read(bytes) where bytes is a Uint8Array, ArrayBuffer or any ArrayBufferView. readFile() and writeFile() are the only filesystem-bound helpers and are Node-only. For files too large to hold in memory, see streaming reads.

API reference

The public surface is small and synchronous where it can be. Everything below is exported from the package root except streaming (sheet-lite/stream) and the incremental writer (sheet-lite/write), which live behind their own subpath entry points.

ts 
import {
  Workbook,
  Worksheet,
  Row,
  Cell,
  Column,
  ValueType,
  typeOf,
  serialToDate,
  dateToSerial,
  SheetLiteError,
  ZipSecurityError,
  ZipUnsupportedError,
} from 'sheet-lite';

// Read-only streaming, in its own entry point:
import { StreamingWorkbook } from 'sheet-lite/stream';

// Incremental, bounded-memory creation (on `main`), in its own entry point:
import { WorkbookWriter } from 'sheet-lite/write';

type Styles

Style assignments are ExcelJS-compatible shapes. They are deduplicated in xl/styles.xml — an identical style the file already carries is reused instead of written twice — and a style edit that resolves back to the cell's existing formatting is a byte-level no-op.

ts 
interface BorderSideProps {
  style?: BorderStyleName;          // one of the 13 OOXML line styles
  color?: { argb?: string };        // ARGB, e.g. 'FF00B0F0'
}

interface BorderProps {
  top?: BorderSideProps;
  bottom?: BorderSideProps;
  left?: BorderSideProps;
  right?: BorderSideProps;
  diagonal?: BorderSideProps;
  diagonalUp?: boolean;
  diagonalDown?: boolean;
}

interface AlignmentProps {
  horizontal?: 'left' | 'center' | 'right' | 'fill' | 'justify' | 'centerContinuous' | 'distributed';
  vertical?: 'top' | 'center' | 'bottom' | 'justify' | 'distributed';
  wrapText?: boolean;
  shrinkToFit?: boolean;
  indent?: number;
  textRotation?: number;            // 0-90, 91-180, 255 = vertical
  readingOrder?: 0 | 1 | 2;
}

All 13 OOXML line styles are supported: thin, medium, thick, dashed, dotted, double, hair, mediumDashed, dashDot, slantDashDot, mediumDashDot, dashDotDot, mediumDashDotDot.

Border colors are ARGB only. Theme and indexed colors on pre-existing borders are preserved in the file but not exposed through the API. Rich-text run fonts model bold, italic, underline, size, color and name; other run properties are not modeled. Alignment uses the OOXML vocabulary — ExcelJS reads our vertical: 'center' back as its 'middle' alias.

class Column

Returned by worksheet.getColumn(). Width and hidden state persist through surgical <cols> edits: existing <col> ranges are split, never destroyed, so other columns keep their attributes.

Member Signature Description
number readonly number: number 1-based column number (1 = A).
letter get letter: string Column letter, e.g. "A".
width get/set width: number | undefined Column width; setting it implies customWidth. undefined clears it.
hidden get/set hidden: boolean Hide or unhide the column.

union CellValue

Values are modelled to align with ExcelJS's CellValue, so migration is straightforward:

ts 
type RichTextRun = { text: string; font?: FontProps };
type RichTextValue = { richText: RichTextRun[] };

type CellValue =
  | null
  | number
  | string
  | boolean
  | Date
  | { error: string }
  | { formula: string; result?: CellValue }
  | { richText: RichTextRun[] };

Cell.type and the exported typeOf() report the kind as a ValueTypeName. The ValueType map gives the numeric constants:

ValueType Value Example
Null0null
Number11234.56
String2'North'
Date3new Date()
Boolean4true
Formula5{ formula: 'A1+B1' }
Error6{ error: '#DIV/0!' }

Values are read from strings, numbers, booleans, dates (both the 1900 and 1904 systems), formulas (with their cached result), errors, and inline/shared strings. A string carrying formatting runs is returned as { richText } — the three readers (inline strings, the incremental shared-strings parser and the streaming reader) share one run collector, so they never disagree. To get the flattened text back, use value.richText.map((run) => run.text).join('').

class StreamingWorkbook

Read-only, bounded-memory reads from sheet-lite/stream. It reads the small package parts up front and then walks worksheet rows one at a time, so a multi-gigabyte file reads with a few MB of live heap. Values and types are identical to the eager reader.

ts 
import { StreamingWorkbook } from 'sheet-lite/stream';

const wb = await StreamingWorkbook.open('./huge.xlsx'); // Node file path
// ...or an in-memory buffer: StreamingWorkbook.open(bytes)

for (const sheet of wb.sheets) console.log(sheet.name, sheet.sheetId);

for await (const row of wb.getSheet('Data')!.readRows()) {
  console.log(row.number); // 1, 2, 3, …
  for (const cell of row.cells) console.log(cell.ref, cell.value, cell.type);
}

await wb.close();

sheetNames get sheetNames: string[] Sheet names in package order.

Streaming mode is deliberately read-only: there is no patch or write path, so editing still needs the eager Workbook. ReadableStream input is not supported (ZIP has no seeking and the EOCD lives at the end) — pass a file path or a buffer. sharedStrings.xml is parsed incrementally but the string table itself stays in memory, so sheets with millions of unique strings are bounded by that table rather than by the row count.

class WorkbookWriter

Incremental, bounded-memory creation from sheet-lite/write (on main). Rows are serialized, deflated and streamed to the target as they are added, so a million-row sheet never sits in memory. Reach it lazily from the root with Workbook.create().

ts 
import { WorkbookWriter } from 'sheet-lite/write';

const wb = await WorkbookWriter.create({ file: './huge.xlsx' });
const ws = wb.addWorksheet('Data', { views: [{ state: 'frozen', ySplit: 1 }] });
ws.getColumn('A').width = 20;
ws.addRow(['name', 42, new Date()]).font = { bold: true };
await wb.commit(); // …or: const bytes = await wb.toBuffer()
Member Signature Description
create static create(options?: WorkbookWriterOptions): Promise<WorkbookWriter> { file } streams atomically to a Node file; { sink } to any { write(chunk) }; no target buffers for toBuffer().
addWorksheet addWorksheet(name: string, options?: { views?: SheetViewProps[] }): WriteWorksheet Add a sheet. Rows must be appended one sheet at a time (SHEET_INTERLEAVED).
commit commit(): Promise<void> Finish the archive (writes styles, workbook, rels, content types) and close the target. Idempotent.
abort abort(): void Give up: remove the scratch file, leave the destination untouched. Also runs on await using scope exit.
toBuffer / writeFile toBuffer(): Promise<Uint8Array>
writeFile(path): Promise<void>		 Buffered target only; a file/sink target throws BAD_TARGET.

The writer creates workbooks only — it never edits an existing file, so it makes no preservation claim. Strings are written inline (t="inlineStr"), trading file size for a hard memory bound. Values, styles and the emitted <c> markup match the eager writer by construction (they share the serializer).

class Errors

Type code Thrown when
SheetLiteError varies, e.g. 'NOT_XLSX' The base class. Every error carries a stable machine-readable code.
ZipSecurityError 'ZIP_SECURITY' The archive violates a safety limit: path traversal, too many entries, oversized parts or a suspicious compression ratio.
ZipUnsupportedError 'ZIP_UNSUPPORTED' The archive uses a ZIP feature we do not support: zip64, encryption, unknown compression methods or multi-disk archives.

Limits are enforced on the ZIP structure before inflation, every entry is CRC-32 verified, and the streaming path applies the exact same rules. Coded errors you can branch on:

code Meaning
NOT_XLSXThe input isn't a valid XLSX package (or a streaming sheet part is missing).
ZIP_SECURITYPath traversal, entry-count, size or compression-ratio limit exceeded.
ZIP_UNSUPPORTEDzip64, encryption, unknown compression method or multi-disk archive.
SHEET_EXISTSaddWorksheet() with a name the workbook already uses.
BAD_SHEET_NAMEEmpty name, longer than 31 characters, or containing : \ / ? * [ ].
SHEET_NOT_FOUNDremoveWorksheet() / streaming readRows() with an unknown sheet.
LAST_SHEETRefusing to remove the last remaining sheet — a workbook must keep at least one.

ts 
import { Workbook, SheetLiteError, ZipSecurityError } from 'sheet-lite';

try {
  const wb = await Workbook.readFile('./maybe-not-excel.xlsx');
} catch (error) {
  if (error instanceof ZipSecurityError) {
    console.error('Rejected unsafe archive:', error.code);
  } else if (error instanceof SheetLiteError) {
    console.error('Invalid package:', error.code);
  } else {
    throw error;
  }
}

ZIP data descriptors (flag bit 3) are accepted since 0.4.0 — the central directory carries the real CRC and sizes — so files written by streaming writers open normally.

Examples

Copy-pasteable snippets. Every write below preserves the rest of the file; the streaming example is read-only.

1 · Read values

Read individual cells by A1 reference or by row/column, or walk every populated row with eachRow.

ts 
import { Workbook } from 'sheet-lite';

const wb = await Workbook.readFile('./report.xlsx');
const ws = wb.getWorksheet('Sheet1')!;

// Random access
const a1 = ws.getCell('A1');
console.log(a1.value); // e.g. 'Region'
console.log(a1.type);  // 'String'

// Same cell, by 1-based coordinates
const b2 = ws.getCell(2, 2);
console.log(b2.address, b2.value); // 'B2', 128

// Iterate populated rows in ascending order
ws.eachRow((row, rowNumber) => {
  const values = row.cells.map((cell) => cell.value);
  console.log(rowNumber, values);
});

2 · Edit a cell and preserve formatting

Assigning to value registers a patch for that cell only. Its original style index — fonts, fills, borders and number format — is retained, and every other byte of the sheet XML is carried over as-is.

ts 
import { Workbook } from 'sheet-lite';

const wb = await Workbook.readFile('./report.xlsx');
const ws = wb.getWorksheet('Sheet1')!;

// Patch a single styled cell — the surrounding file stays intact
ws.getCell('B2').value = 1234.56;

await wb.writeFile('./report-edited.xlsx');
// data validations, conditional formatting, merges and images survive

If you change nothing at all, toBuffer() returns the original bytes verbatim — a true no-op round-trip.

3 · Add rows

addRow appends below the last populated row, starting at column A. It accepts the same CellValue union, and returns the created row.

ts 
import { Workbook } from 'sheet-lite';

const wb = await Workbook.readFile('./report.xlsx');
const ws = wb.getWorksheet('Sheet1')!;

ws.addRow(['North', 128, true]);
ws.addRow(['South', 94, false]);

// addRow returns the new Row
const row = ws.addRow(['West', 61, true]);
console.log(row.number);          // e.g. 42
console.log(row.getCell(1).value); // 'West'

await wb.writeFile('./report-edited.xlsx');

4 · Working with dates

Date cells are decoded into native Date objects, honouring both the 1900 and 1904 date systems. Writing a Date stores the Excel serial number; when you patch a cell that already carries a date number format, that format is preserved so Excel still renders a date.

ts 
import { Workbook } from 'sheet-lite';

const wb = await Workbook.readFile('./report.xlsx');
const ws = wb.getWorksheet('Sheet1')!;

// Reading: date-formatted cells come back as Date instances
const when = ws.getCell('B3').value;
if (when instanceof Date) {
  console.log(when.toISOString());
}

// Writing: a Date becomes its Excel serial number
ws.getCell('B3').value = new Date('2026-01-15T00:00:00Z');

await wb.writeFile('./report-edited.xlsx');

Need manual control? The helpers serialToDate() and dateToSerial() are exported for converting between Excel serial numbers and Date values.

5 · Formulas

A formula cell is read as { formula, result }, where result is Excel's cached value. To write one, provide the formula text and, optionally, the cached result.

ts 
import { Workbook } from 'sheet-lite';

const wb = await Workbook.readFile('./report.xlsx');
const ws = wb.getWorksheet('Sheet1')!;

// Reading a formula exposes its text and cached result
const total = ws.getCell('B5').value;
// { formula: 'SUM(B2:B4)', result: 1234.56 }

// Writing a formula (result is optional)
ws.getCell('B5').value = { formula: 'SUM(B2:B4)', result: 1234.56 };

await wb.writeFile('./report-edited.xlsx');

sheet-lite does not evaluate formulas. The result is the cached value Excel stored — supply it when you want readers that don't recalculate to show a value.

6 · Borders and alignment

cell.border takes the ExcelJS shape and supports all 13 OOXML line styles; cell.alignment uses the OOXML vocabulary. Setting one side merges over the cell's existing border, and identical styles are deduplicated in xl/styles.xml instead of written twice.

ts 
import { Workbook } from 'sheet-lite';

const wb = await Workbook.readFile('./report.xlsx');
const ws = wb.getWorksheet('Sheet1')!;

ws.getCell('C3').border = {
  top: { style: 'thin', color: { argb: 'FF00B0F0' } },
  bottom: { style: 'double' },
};
ws.getCell('D4').alignment = {
  horizontal: 'center',
  vertical: 'center',
  wrapText: true,
};

// Later edits merge — 'left' keeps the thin top border set above
ws.getCell('C3').border = { left: { style: 'medium' } };

// Read back what the file actually carries
console.log(ws.getCell('C3').border);
console.log(ws.getCell('D4').alignment);

await wb.writeFile('./report-edited.xlsx');

Border colors are ARGB only. Theme and indexed colors on pre-existing borders are preserved in the file but not exposed through the API. An empty {} (or re-applying the style a cell already has) is a byte-level no-op.

7 · Rich text

Rich text round-trips: write { richText: [{ text, font? }, …] } and it is stored as inline <r> runs; read a cell whose inline or shared string carries runs and you get the same shape back.

ts 
import { Workbook } from 'sheet-lite';

const wb = await Workbook.readFile('./report.xlsx');
const ws = wb.getWorksheet('Sheet1')!;

// Writing runs
ws.getCell('D4').value = {
  richText: [
    { text: 'Total: ' },
    { text: '1 234 €', font: { bold: true, color: 'FFFF0000' } },
  ],
};

// Reading runs back
const cell = ws.getCell('D4');
if (cell.value && typeof cell.value === 'object' && 'richText' in cell.value) {
  console.log(cell.value.richText);  // [{ text: 'Total: ' }, { text: '1 234 €', font: … }]
  console.log(cell.value.richText.map((run) => run.text).join('')); // 'Total: 1 234 €'
}

await wb.writeFile('./report-edited.xlsx');

Rich text is written as inline strings, never shared strings; shared strings containing runs are read as { richText } but never written by us. Run fonts model bold, italic, underline, size, color and name. Plain strings stay plain.

8 · Sheet structure

Add and remove sheets, size columns and rows, and freeze panes. All of it is surgical, and works on files that have no styles.xml or no sharedStrings.xml.

ts 
import { Workbook } from 'sheet-lite';

const wb = await Workbook.readFile('./report.xlsx');

// Add a sheet (registers content type, relationship and <sheets> entry)
const summary = wb.addWorksheet('Summary', {
  views: [{ state: 'frozen', ySplit: 1 }],
});
summary.getCell('A1').value = 'Total';
summary.getCell('A1').font = { bold: true };

// Columns and rows
summary.getColumn('A').width = 24;
summary.getColumn(2).hidden = true;
summary.getRow(1).height = 22;

// Freeze panes on an existing sheet (ExcelJS-compatible)
const ws = wb.getWorksheet('Data')!;
ws.views = [{ state: 'frozen', xSplit: 2, ySplit: 3 }];
console.log(ws.views); // read back: [{ state: 'frozen', xSplit: 2, ySplit: 3, … }]

// Remove a sheet — its part, rels and registration go away
wb.removeWorksheet('OldSheet');

await wb.writeFile('./report-edited.xlsx');

New worksheets are plain: values and optional frozen panes, no charts, tables, images or conditional formatting. Removing the last remaining sheet is rejected with LAST_SHEET. Existing <col> ranges are split rather than rewritten, so neighbouring columns keep their widths.

9 · Streaming reads

For files too big to hold in memory, walk rows with a bounded memory ceiling. The streaming entry point is read-only: it never patches and never writes.

ts 
import { StreamingWorkbook } from 'sheet-lite/stream';

const wb = await StreamingWorkbook.open('./huge.xlsx'); // Node file path
// ...or an in-memory buffer: StreamingWorkbook.open(bytes)

console.log(wb.sheetNames);

let total = 0;
for await (const row of wb.getSheet('Data')!.readRows()) {
  for (const cell of row.cells) {
    if (cell.type === 'Number') total += cell.value as number;
  }
}
console.log(total);

await wb.close(); // closes the file handle

A 100 000 × 8 sheet streams in 10.2 MB of live heap versus 673 MB for Workbook.read. The same API is available lazily from the main entry as await Workbook.openStream('./huge.xlsx'). Pass a file path or a buffer — ReadableStream input is not supported.

10 · Creating large files

The write counterpart of streaming: build a workbook from scratch and append rows one by one. Each row is serialized, deflated and streamed to the target, so memory stays bounded however large the sheet is.

ts 
import { Workbook } from 'sheet-lite';           // lazy alias…
// …or, without the indirection:
// import { WorkbookWriter } from 'sheet-lite/write';

const wb = await Workbook.create({ file: './huge.xlsx' }); // atomic file target
const ws = wb.addWorksheet('Data', { views: [{ state: 'frozen', ySplit: 1 }] });
ws.getColumn('A').width = 20;

for (let i = 1; i <= 1_000_000; i++) {
  ws.addRow([i, `row ${i}`, i / 2]).font = { size: 11 };
}

await wb.commit(); // …or: const bytes = await wb.toBuffer()

A { file } target is atomic: bytes go to a sibling temp file renamed over the destination only once the archive is complete, so a failure mid-loop leaves your previous file intact. Strings are written inline (t="inlineStr") to keep the memory bound flat. The writer creates new workbooks; editing an existing file uses the eager patch path (Workbook.read()).

Limitations

sheet-lite is deliberately narrower than ExcelJS and SheetJS. Here is the honest list, so you can decide whether it fits before you install it.

Out of scope What that means
.xls / .xlsb, encryption, CSV OOXML only. Archives with zip64, encryption, unknown compression methods or multi-disk structures are rejected with ZIP_UNSUPPORTED instead of being guessed at.
Formula evaluation Formula cells carry their cached result only — the same as ExcelJS and SheetJS. sheet-lite never recalculates.
Creating charts, pivot tables, images, comments, conditional formatting These are preserved, not created: they survive a round-trip untouched, but there is no API to add them.
Rich content on new sheets addWorksheet() creates plain worksheets only — values, styles and optional frozen panes. Add rich parts later by editing.
Orphan parts on removal removeWorksheet() removes the sheet, its rels and its registration, drops a stale calcChain.xml, and (on main) prunes the parts only that sheet owned. Anything a surviving relationship still points at is kept.
Multiple sheet views Only the first sheetView of a sheet is editable through views; every other view and attribute is preserved as-is.
Border theme & indexed colors Border colors you set are ARGB-only. Theme/indexed colors already in the file are preserved, but not exposed through the API.
Streaming reads are read-only sheet-lite/stream never patches and never writes. Editing an existing file needs the eager Workbook, which keeps untouched parts in memory to re-serialize them verbatim. Creating a new workbook with bounded memory is sheet-lite/write (Workbook.create, on main).
ReadableStream input A ZIP has no seeking and its EOCD lives at the end, so a stream would have to be buffered anyway. Pass a Node file path or a buffer.
Eager reads of huge files Workbook.read inflates the whole archive and parses the worksheet into memory. Use sheet-lite/stream for large files.
Verification against Excel There is no Excel in CI. The gate proves that LibreOffice re-opens every edited file without repair — LibreOffice is not Excel, so treat the corpus as a strong signal, not a guarantee.

Next release — on main, not yet on npm

These are implemented and tested on main and will ship in the next version; the published sheet-lite@0.5.0 does not have them yet:
